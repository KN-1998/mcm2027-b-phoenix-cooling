# 建模手自我规范（MODELER_STANDARDS）

> 来源：2026-11-19 培训摘录 + 《2.5 分复盘与三角色改进方案》+ 《交付后核对清单》+ 本次 B 题三轮审查的教训。
> 适用：我作为建模手的**所有交付**。每条都可验收——不能因为文档里出现关键词就算做到。
> 与 `LESSONS_FROM_A.md` 的关系：那份是 A 题的教训清单，这份是**操作规范**，按它写东西。

---

## 0. 一句话

**评委要看的不是"你会做模型"，而是"你能从机制推出方程、用真实数据检验、并且讲清哪里会失效"。**
建模手交付的不是"一个模型"，是**一条可检验的方程链 + 一张假设卡 + 一份失效条件**。

## 1. 十条硬规范（每条都带验收方式）

### R1 公式必须有出处或推导过程

| 类型 | 要求 | 验收 |
|---|---|---|
| 文献原式 | 直接出处（作者/年份/式号）+ **适用条件** | 能在原文找到该式 |
| 改造式 | 写清"改了哪一项、为什么改、改后还适用吗" | 逐项对照原式 |
| 自推式 | 推导步骤可复述（收支/几何/机制） | 建模手能 5 分钟白板推完 |
| 定义式 | 说明设计理由（为什么这样定义而不是别的） | 一句话理由 + 反例 |

**禁止**：编一个公式、贴一个没读过的引用、把"常见做法"当出处。

### R2 一条主方程链，不散

围绕**一个核心关系**连续推导：机制 → 最小模型 → 解释不了的现象 → 必要修正 → 可检验预测。
可以有多状态、多方程，但**必须能指回同一条链**。
验收：任意后续公式，都能回答"它从哪一条式演化来"。

### R3 每条假设五件事齐全

| 字段 | 要求 |
|---|---|
| 必要性 | 不假设会怎样（模型不可解 / 参数不可辨识） |
| 合理性 | 依据（文献/观测/量级）或明确标 ASSUME |
| 公式落点 | 进到哪一式、哪一项 |
| 失效后果 | 假设不成立时**哪条结论会变** |
| 检查方法 | 用哪个数据/哪个实验能证伪 |

**禁止**："通常如此""一般认为"作为理由。

### R4 量纲、初值、边界、有效范围明确

每个状态量写清：单位、取值范围、初值、边界条件。
明确**模型在哪里不适用**（比"适用范围广"更值钱）。
验收：能用一句话说出"这个模型不能回答什么问题"。

### R5 五种证据分开，不互相替代

| 证据 | 能回答 | 不能推出 |
|---|---|---|
| 原始资料/文献 | 数字从哪来 | 模型有效 |
| 数值检验（守恒/对拍/边界） | 代码实现对 | 现实会这样 |
| 蒙特卡洛 | 给定分布下的波动 | 覆盖认知不确定性 |
| 敏感性/结构对照 | 哪些假设改变结论 | 替代实证验证 |
| **实证验证** | 未参与定参的数据能否被解释 | —— |

**只要缺最后一项，结论必须降级为"条件情景"。**

### R6 敏感性分析是必做项，不是加分项

- 至少 OAT 扫描关键参数，报告**结论何时翻转**；
- OAT 范围不同不能称为"重要性排序"；
- 敏感性 ≠ 实证验证。

### R7 先有简单基线，再谈复杂模型

必须报告：简单基线是什么、复杂模型比它好多少、好在哪。
复杂模型在留出上不如基线 → **分析失败原因，修模或退回基线**，不是加限制段落。

### R8 数据要能追到原始文件

每个外部数字：机构/作者、日期、地点、单位、页码或行号。
标签必须区分：**原始观测 / 跨地区参考 / 模型派生 / 工作假设**。
文献量级不能升级成本地实测。

### R9 交付的是"推导 + 假设 + 数据 + 预期现象 + 失效条件"

不是"完整方程 + 方法名"。另两位队员必须能复述每个项、每个符号、每个假设。

### R10 不用 AI 腔，不美化失败

- 摘要讲故事（怎么想到、为什么这个、发现了什么），不是平铺工程流程；
- 验证失败就写失败，并说明**因此改了什么**；
- 不得编造研究过程、不得删减真实使用记录。

## 2. 建模手交付清单（每次任务）

| # | 交付物 | 验收 |
|---|---|---|
| M1 | 问题卡：管理问题、目标量、观测定义、时空尺度、允许的结论 | 每个输出都能说清怎么测 |
| M2 | 数据可行性表：坐标/日期/单位/误差/本地或异地/拟合或验证 | 不用验证集调参 |
| M3 | 核心方程推导说明（≤2 页）：控制体/机制图、收支式、几何转换、本构出处、近似步骤 | 5 分钟白板推完 |
| M4 | **假设卡**（见 §3） | 每条有失效后果与检查方法 |
| M5 | 实验设计：简单基线、必要的消融、同外生输入的对比 | 一次只回答一个机制问题 |
| M6 | 决策卡：谁测什么、何时行动、资源约束、无解时怎么办 | 没有数据支撑就缩小结论 |

**最严重的缺口是 R5（没有实证验证）**——这与 A 题 2.5 分的头号失分点一模一样。
必须写进论文：**我们的结果是条件情景，不是实测预测**。

## 5. 每次交付前的 7 问自检（脱稿回答）

1. 我们预测/解释的量是什么？现场怎么测？
2. 核心方程怎么从机制推出来？每个项为什么存在？
3. 哪些来自文献、哪些自己推、哪些只是工作假设？
4. 哪些数据定参、哪些留作检验？比简单基线好多少？
5. 哪个最关键假设不成立时，哪条结论会变？
6. 随机挑一个数，能否从配置和原始输出重算？
7. 我们最明显的失败是什么？因此改了什么？

**答不上来的，进返工表，不进论文。**

---

## 6. 与代码手/论文手的接口

- 给代码手：公式—变量—配置键—函数—输出字段的对照表（不是只给公式）；
- 给论文手：推导 + 假设卡 + 证据表 + 失效条件（不是只给"结果"）；
- **共用一张结论证据表**：结论 → 假设/公式 → 数据 → 代码 → 结果文件 → 图表位置 → 限制与复核人。
