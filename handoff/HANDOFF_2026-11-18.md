## 2. 模型现在是什么

**结构**：12 个规划区 × （真实固定网络 + 8 个候选 MCH）× 7 天 × 3 个时段。

```
demand.csv ──┐
             ├─> loaders.load_instance ──> Instance
sites.csv ───┤         │
access.csv ──┘         ├─> incoming 钩子（若 data/incoming/ 有真实文件则自动覆盖）
                       │
                       ├─> static.solve_static      ← 枚举 8 选 p × 跨时段单 LP
                       ├─> static.solve_static_fair ← ε 约束（日未满足率）
                       ├─> dynamic.solve_week_dp    ← 七天 DP（唯一实现）
                       ├─> disruption.plan_response ← 24h 响应时刻表（车队守恒）
                       └─> policy.five_year_plan    ← 仍是规则草案
```

## 3. 关键结果

### 3.1 真实网络 vs 合成网络（最重要的一张表）

| 口径 | 30 分钟内有降温中心的区 |
|---|---|
| 合成网络（每区一个中心） | 8/12 |
| **真实 MAG 网络 · 步行** | **1/12** |
| 真实 · 步行 45 / 60 分钟 | 5/12 / 8/12 |
| **真实 · 公交 30 分钟** | **8/12** |

覆盖率曲线（未满足人次/日）：

| p | 合成·步行 | 真实·步行 | 真实·公交 |
|---|---|---|---|
| 0 | 305.5 | **474.8** | 258.4 |
| 2 | 248.6 | 360.6 | 191.3 |
| 3 | 227.3 | 322.5 | 169.6 |
| 4 | 206.1 | 284.8 | 148.3 |
| 7 | — | 212.6 | 122.0 |
| 8 | 154.2 | **212.6（饱和）** | **122.0（饱和）** |

> **必须标注**：区质心是单点，区内人口分散 → 以质心计距离**高估**不可达。所以同时报 30/45/60 分钟与公交口径。

### 3.2 政策杠杆（合成网络 p=3，基线 227.3）

| 杠杆 | 未满足 | 变化 |
|---|---|---|
| 固定中心延时到 22:00 | 107.8 | **−119.5** |
| 两者都做（延时 + 扩容） | 97.2 | −130.1 |
| 加第 4 / 6 台枢纽 | 206.1 / 168.6 | −21.2 / −58.7 |
| 固定中心容量 50→100 | 227.3 | **±0（容量不绑定）** |
| 移动枢纽延时 | 227.3 | **±0** |

**排序：开门时间 > 可達性 > 车队规模 > 单站容量（≈0）**

> 单位注意：延时收益按 day0 算为 −119.5/日；**逐日重算的七日合计是 −858.7**，不是 836.5。

### 3.3 Q3 搬迁（七日累计，不是日）

| 冲击 | 固定部署 | 动态 | 搬迁收益（七日） | 日均 |
|---|---|---|---|---|
| 无 | 1768.4 | 1768.4 | **0** | 0 |
| D05 ×2 | 1798.2 | 1784.3 | +13.9 | +2.0 |
| D01 ×5 | 1824.8 | 1812.4 | +12.4 | +1.8 |

对比延时（−858.7/七日），搬迁收益约 **1.6%**。

### 3.4 Q4 中断（R1 修正后）

| 类型 | 损坏 | 健康车队 | 不响应 | 响应 | 收益 |
|---|---|---|---|---|---|
| 位置不可用 | R01 / C01 | 3 | 301.2 / 283.9 | 同 | **0** |
| **车辆故障** | MCH-3 / MCH-7 | **2** | 348.8 / 305.1 | 同 | **0** |
| 位置不可用（可搬） | MCH-3 场地 | 3 | 348.8 | 327.6 | +21.2（1.0 h） |

压力测试（100 次）：24 h 可行率 100%，最长 1.82 h，收益 **P10 = −21.3 / P50 = 0 / P90 = +21.2**。

> **负收益出现**：把停服时间算进去，搬可能比不搬更差。

## 4. 三轮审查修了什么（可追溯到提交）

### 第一轮（P1-1…P1-6）
贪心→LP 分配；时段容量不再重复折减；capacity 参数生效；Q4 情景隔离；
需求改按峰值周总量标定；来源标签字段化。

### 第二轮（A1–A7）
A1 冲击副本真正进入求解；A2 公平改为**跨时段单 LP**（ε 施加在日未满足率）；
A3 无车率 **3.04% → 7.42%**（B25044: 003 + **010**）；A4 首日不计停服 + 固定方案强制入候选；
A5 单位改七日累计；A6 选址与评价容量口径统一；A7 多选比例不可相加（并集界 54.5–94.8%）。

### 第三轮（R1–R6）
R1 **车队守恒**：位置不可用 ≠ 车辆故障，故障车不得再投入服务；
R2 时刻表去重 setup、按排队折算停服、超预算不计可执行收益；
R3 Q3 停服按**实际行程**；R4 夜间/傍晚专用站不再被过滤（41.5 / 16.0 恢复）；
R5 pipeline 退出码 0；R6 incoming 字段映射/新站/未知列全部入日志。

### 作废记录（引用前必查）

| 曾发布 | 为什么错 | 现在 |
|---|---|---|
| 延时 1.8 倍 | 容量折扣模型 | 2.2 倍（−119.5 vs −58.7） |
| 公平代价 +23% | 贪心分配 | 不存在取舍 |
| 未满足全为 no_access | 归因算了未选候选点 | 可達 25 / 容量 68 / 选点 116 |
| 故障后搬迁 +21.2 | 违反车队守恒 | 仅"位置不可用"成立 |
| 24 h 从不紧张 | 抽样只取候选点 | 需按车队守恒重述 |
| 14.15 人次/日 | 单位错（七日累计） | 1.99/日 |
| 94% 依赖步行公交 | 多选相加 | 54.5%–94.8% 并集界 |
