# Q5：把资产、开工和年度合同分开的五年规划

交付阶段：建模实现与条件情景比较。2026-11-20。实际 AI 辅助：模型推导整理、代码修改、测试与审阅；不将本文冒充队员已完成的独立研究或答辩记录。

## 要回答的管理问题与观测量

在 2027—2031 年逐年预算约束下，何年购置、多少辆开工、是否购买延时与接驳服务？评价量是**室内降温服务未满足人次/代表日**，由预约、进站和拒绝服务记录按同一人次口径核查。它不是独立人数、死亡人数或货币健康收益。现场部署前还需真实需求、固定站接待能力、报价、人员与许可记录；当前没有这些独立验证序列，因此本模块交付条件情景规划和可执行的更新规则，不交采购金额的实证最优建议。

年度需求仍使用同一输入实例的第 0 日需求乘预设热情景系数。没有根据五年真实逐日天气重新预测。默认 `operating_days=1`，五年目标是五个代表日分数之和；如指定 153 天，则只是“每日相同”的重复情景，不得改称验证过的年度客流预测。

## 从年度资源收支推到有限状态模型

内层服务分配仍来自同一条 `需求 = 已服务 + 未满足` 的守恒链。给定年度开工数、时段和可达性，内层选址/分配模型得到

\[
u_y(a,e,s)=\sum_i D_{iy}-\sum_{ijh}x_{ijhy},\qquad [u_y]=\text{人次/代表日}.
\tag{Q5.1}
\]

这里 `a` 为当年开工车数，`e∈{无延时,21,22}` 为当年固定室内中心延时合同，`s∈{0,1}` 是接驳可达阈值情景。`None` 保留数据原时段，不再把固定中心统一截到 17 点、把 MCH 截到 19 点；延长关门时间也不会缩短已经营业更晚的站点。MAG 日历只延长**原本已知营业日**的日间窗口；unknown、明确关闭与跨夜关门钟不由延时合同推断开放。原关门时刻留在 `source_close_hour`，修改规则标 `open_policy_assumption`，实际分配读取同一修改后的逐日日历。每日总接待上限不因延时增加，故这是服务**时间位置**的改变。如果实际延时新增人员和日接待量，应另测每小时处理率再改容量式。

先区分年初自有资产 `O_y`、新增购买 `B_y` 与当年开工 `A_y`。停运不会使汽车消失，购买也不强制当年开工：当年有余款而未来预算不足时，购买后保留闲置库存可能必要。资产收支为

\[
O_{y+1}=O_y+B_y,\qquad 0\le B_y\le p_{max}-O_y,\qquad 0\le A_y\le O_{y+1}\le p_{max}.
\tag{Q5.2}
\]

`O,A,B` 的单位均为辆。初值 `O_2027=p_start`；初始采购视为沉没成本。当前无报废收益和储存成本数据，因此不设主动报废，输出 `retire=0`，库存可以留存。没有通胀、采购提前期、车辆退化和预算结转；这些是明确工作假设，不能从方程中的零读成现实中不花钱。

每年完整账目而不是只给新增车辆计费：

\[
C_y=c_BB_y+c_AA_y+c_E(e_y)+c_Ss_y\le K_y,\qquad[C_y]=\mathrm{USD/year}.
\tag{Q5.3}
\]

所有单价和预算均为 `ASSUME`。延时与接驳按年度可续签、可取消合同处理，不会因某年使用而永久强制续费。零开工、无延时、无接驳总是预算为零时的合法行动；不会出现“无解但预算通过”。

给定一条完全指定的未来热情景，Bellman 状态只有自有库存 `O`。令 `d_y` 为假设重复的代表日数，`w_y` 为内层最差区未满足率，则求

\[
\min_{lex}\left(\sum_y d_y u_y,\;\sum_y d_y w_y,\;\sum_y C_y\right).
\tag{Q5.4}
\]

这是自推的有限资源收支与枚举递推，未把公式贴给未读文献背书。每年穷举 `B=0..pmax−O`、`A=0..O+B`、三种延时、两种接驳，预算筛选后更新库存；对相同库存仅保留累计字典序目标最小的路径。未来可行动集合只依赖库存、下一年预算与外生需求，故同库存的劣路径可以安全删除。在此假设下是有限行动集上的精确 DP；内层若被换成启发式，只能说该内层价值表上的 DP 最优。它也不是未知未来下的随机最优。

## 同一外生输入下的对照与反例

`dp`、`rolling` 和 `maintain` 共享同一热路径、需求表、价格表、年度预算和内层价值缓存。`rolling` 枚举**相同**行动集，只看当年服务、最差区率及费用；因此 DP 与其差异来自跨年考虑。`maintain` 不买车、不购买延时或接驳，允许预算不足时暂停部分已有车辆；它是现有资产基线，行动集较小的差异明确保留。

独立手算反例：初始零辆，最多两辆，购置每辆 2、运营每辆每年 1，预算 `[6,2]`，需求 `[1,2]`，每辆可服务 1。逐年滚动首年买一辆，次年预算 2 买不起第二辆并开工，累计未满足 1。DP 首年买两辆、只开工一辆花 5，次年两辆开工只付运营 2，累计未满足 0。这也说明为什么不能把购买数锁死成 `max(0,开工−已有)`：强制首年两辆开工会无必要地多花 1。该反例验证跨期状态确实进入计算；不是用增加随机抽样制造改善。

`tests/test_q5_investment.py` 还检查：八辆中首年暂停一辆、次年恢复时不重复购买；零预算零车辆可行；允许一次购买四辆；年度资产守恒、完整成本；对两至三年小模型独立全序列穷举；延时合同到期；不更改输入营业时间与需求；逐日日历延时确实进入实际服务 LP，且不打开 unknown/明确关闭日。数值测试只说明实现，不证明 Phoenix 的真实需求或成本。

运行：

```powershell
python -m pytest tests/test_q5_investment.py -q
python -m src.exp.run_q5_plan --out tmp/reproduce_q5
```

输出：`plan.csv` 为 DP 年度轨迹；`baselines.csv` 为两种基线；`comparison.csv` 为同情景累计差；`cost_sensitivity.csv` 为基准预算/热情景下购置与运营价格倍率 0.5、0.75、1、1.25、1.5、2（合同价格保持固定）的行动变化。扫描范围是工作假设，不是成本置信区间，不据此作标准化参数重要性排序。`summary.json` 记录目标、有限行动、状态假设和条件最优范围，`run_meta.json` 记录实际运行版本；脏工作区的试跑不作冻结版证据。
