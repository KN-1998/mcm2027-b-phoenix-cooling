# 数据接入、真实输入核验与结论边界

本轮接手日期：2026-11-20。作者：Codex 数据子代理；主代理独立复核另记。本文件针对复盘的 M2、C1—C3、C6，不代表三位队员已共同复述或完成现场验证。

## 1. 现在能回答什么

现有资料支持：在给定需求、日容量、交通代理、候选集与成本假设下，比较不同站点、运营日历与调度方案造成的**条件服务缺口**。服务缺口单位为人次/规划日，既不是未服务人数，也不是死亡减少量。

现有资料不能检验：区—日真实想使用降温空间的需求、未到访/被拒绝的需求、真实 MCH 吞吐率或实际公交门到门时间。因此本轮将交付范围收缩为**可复算的条件方案与试点采样设计**，不交实际覆盖率预测、现场部署保证或确定采购数量。数据核验通过没有解除这个范围限制。

## 3. 修复后的数据入口

`src/mch/incoming.py::apply_incoming` 的顺序是：属性变化→仅受影响区的显式需求重算→交通输入→观测需求逐格覆盖。观测格最后写入，避免123人次被派生值覆盖；上一轮overlay已记录的观测格也保留。容量、营业小时、站点类型和坐标变化不会触发需求重算；坐标变化缺少配套交通格时默认报错，同时记录 `stale_access_links`，不生成虚构公交时长。仅显式 `allow_stale_access=True` 可用于查看诊断；默认loader继承报错政策。新站点仍需明确站点构造与可达矩阵，当前overlay拒绝静默追加。未知区/超范围日被记录，负值、NaN、非法比例、容量小数被拒绝。

需求重建只由进入需求式的区属性改变触发，只重建改变的区。以原属性模型值f_old和修改后f_new构造 `D_new = D_old × f_new/f_old`，逐区逐日保留processed场景的既有量级与时间形状；比例只用于避免重置工作参数，不称为新的实证标定。原模型为0而新模型为正时无法识别比例，默认报错，只有调用者显式提供 `meta.demand_scale` 才可填补该退化格。默认D01人口增加1人的测试中总量仅按原区比例微增，不会从约505跳回原始率的约4600人次。`demand_observed.csv` 必须符合研究目标：仅有中心到访数时属于实现服务量，不能直接冒充包含未到访者的总需求。

`src/mch/realnet.py::load_mag_sites` 新增 `start_date`、`horizon_days`、`unknown_hours` 与 `assumed_cooling_capacity`。每站 `extra.calendar_by_day` 保存日期、weekday、原状态及运营窗口，并额外保存前后各一日，供09:00—次09:00服务日窗口交集使用；这不是增加研究天数。`site_on_day(site,day)` 返回当天视图，不改变原站点；缺少当天日历则报错。日历先检查来源Start/End_Date，再检查节日和该weekday；Active=Yes不能延长季节。Century Library周一9—17、周二10—18不再被合并为每天9—18。

默认参考周为2026-07-20—26，**不是2027年未来真实营业表**。空白是unknown；`unknown_hours='closed'` 是保守零可用时长的工作政策，日志写 `conservative_zero_assumed`，不声称源资料证明关闭。可以选 `unknown_hours='error'` 要求使用前补齐。2026-07-03是否按独立日观察假处理尚待确认，不自动继承7月4日规则；调用者可用明确 `holiday_overrides` 记录已核实的选择。

固定站与候选点统一使用距离×1.35/速度的交通代理。transit为 `min(直接步行, 距离/15kmh+10min)`，避免家门旁候选点因先走到远处车站反而需数小时。`meta.access_schedule_routing=False` 明示不是GTFS排班求路。速度、绕行、等车都是工作假设，2027预测必须另做时刻表和现场可达性检查。

`apply_official_demographics(inst)` 是显式候选接口，采用报告派生人口与65+，不更改无车、收入、热暴露或需求。调用后需另行决定需求重算方法。不能因为人口已替换，就把其余脆弱性字段或需求也标为实测。

### 失败后的实际动作

这次没有拿到可识别“未满足需求”的独立观察，因此不拟合一个看似当地精确的需求率，不继续用增加MC次数来补验证。输出降级为条件比较，真实人口接口保持显式，自动人口替换与“实测覆盖率”表述不进入默认运行。未来若能取得到访量，也要先处理容量截断与自选择，不能以到访量等同潜在需求。

## 5. 预登记式采样与验证方案（尚未实施）

该部分是下一步现场/队友取数方案，不是已完成的留出实验。

1. 城市热响应协调员选定参考日历；中心主管逐日记录实际开关门、可用室内席位、停留时间、工作人员、停电、到访/拒绝/排队人次和计数规则。社区外展组补充未到访者的出行障碍与可接受出行时间，避免只对已经到访者估计需求。
2. 在收集前冻结站点和日期范围、目标字段、缺失规则与划分。建议前两次完整热浪为开发集，下一次完整热浪为时间留出；不能随机拆相邻小时来伪装独立。按站点/日期成块报告误差和不确定性。实际日期由获得数据时登记，当前不编造观测日期。
3. 简单基线为“同weekday上一可用周的到访量”；仅用开发集拟合固定参数的需求—容量模型。留出期间保持参数、行动集合与外部热过程固定，比较到访量MAE及计数偏差；零值不用MAPE。若检验未到访需求，需独立外展/拒绝样本，不能沿用到访指标。
4. 在看留出值前登记管理容忍误差，并以简单基线为比较门槛；没有预定容忍度时不得回看结果后选择通过线。复杂模型不及基线，则退回基线/减少参数，不先出确定部署建议。容量、交通、需求率无法分别识别时，不同时拟合所有参数。
5. 城市主管在许可、车辆、停靠、供电、无障碍与配员均核实后才可把条件候选列入试点；无可行位置时报告缺口并转为外展、交通接驳或既有中心延时备选。无车、到访、真实OD和移动成本缺口未补之前，不据本输出承诺覆盖某比例人口或采购最优数量。

## 6. 假设—公式—失效条件

| 假设/来源 | 必要性与公式落点 | 失效后果 | 检查方法 |
|---|---|---|---|
| ASSUME：unknown小时取0 | 已有容量约束需要明确可用窗口；`capacity_in_period`的小时重叠项 | 可能低估服务；不是unknown真实关闭 | 逐站电话/原机构营业表核对；与补齐日历情景配对 |
| ASSUME：固定中心50人次/日 | MAG没有容量；分配式的站点容量上界 | 有限容量下需求/供给变化能改变选址排序 | 记录席位×周转/实际吞吐率；容量OAT与翻转点 |
| ASSUME：距离/速度交通 | 当前没有排班OD；链接阈值A_ij | 线路绕行/车班可能改变可达集合与选择 | 同一日期GTFS OD+直接步行备选、现场实测 |
| SCENARIO：区中心代表全部居民 | 减少空间状态；A_ij由中心点出发 | 偏差可双向，不能声称必然高估不可达 | 人口加权多点、tract空间叠置结构对照 |
| DERIVED：15村映射12规划区 | 题目采用12区；聚合人口/年龄 | 改映射会改需求分布；不是官方界线 | 每村恰好一次、合计守恒、备选分区 |
| ASSUME：潜在需求率与分时占比 | 把人口风险代理转为人次需求；D_it与D_ith | 到访受自选择/容量截断，比例未识别 | 独立需求调查与拒绝记录；不只用已到访量标定 |
