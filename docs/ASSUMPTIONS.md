# B 题假设、定义与失效条件

本卡替换旧版。公式编号对应[核心推导](MODEL_CHAIN.md)，实现细节另见[Q4](TAKEOVER_Q4.md)、[Q5](TAKEOVER_Q5.md)。本题的12个代表区和8个候选点属于训练题情景，不是 Phoenix 官方区划或已批准的项目点。默认 `data/processed` 仍含合成输入，接入真实站点并不会使其余人口、需求、容量和交通时间自动成为观测。

标签：`OBS` 原始资料中的记录；`DERIVED` 按公开步骤变换；`LIT` 文献/异地参考；`SCENARIO` 题设或条件情景；`ASSUME` 缺观测的工作参数；`PLAN` 待管理方确认的行动规则。这里没有把“来源真实”“数值正确”和“现实预测有效”混成一项。

## 主链假设卡

| ID / 假设或定义 | 为什么需要；依据与代价 | 进入公式 / 实现 | 失效后哪条结论会变 | 检查或处置 |
|---|---|---|---|---|
| A01 12区、8点为有限管理对象 | `SCENARIO`；需要明确需求和行动单元。15个官方 urban villages 到12区的映射是本仓库方案，不是官方行政区划 | M1—M6；`data/processed`；`village_to_contest_district.csv` | 区内差异、新候选点与真实部署方案均可能改变排序 | 检查15村恰出现一次、人口总量守恒；比较更细区划。不能用“题目有12区”证明当前合成位置正确 |
| A02 目标是室内降温服务人次 | `SCENARIO/定义`；与题目每日接待上限一致。重复来访可重复计人次；饮水点不等同空调休息空间 | M1、M3；`schema`、`_active_sites` | 若目标改为独立人数、饮水或健康结局，当前需求和容量不可直接使用 | 统一登记到访、时段、拒绝服务与重复口径；不由服务人次换算避免死亡 |
| A03 潜在需求缺独立观测 | `ASSUME`；人口×暴露×脆弱性×日因子是工作需求分配式。官方部分中心已实现到访量受地点、开放时间和选择影响，只能作量级参考，不等于全市潜在需求 | M1；`demand.district_day_demand`、输入 `demand.csv` | 需求总量与空间份额都会影响未满足量、所选站点和边际收益 | 保留原到访样本范围；补拒绝服务和未到访调查。需求0.5/1/2倍仅是情景，不是置信区间 |
| A04 需求缩放不推出同比缺口 | `数学边界`；在有限容量下，服务量随需求变化且可能饱和，不能使用旧版“需求两倍则未满足两倍、排序不变” | M1、M3 | 站点、增车数、延时与接驳排序可能翻转 | 在固定容量/时段/交通表下重新解每个规模情景；记录 `unmet_total`、`chosen`，不缩放旧结果 |
| A05 服务日从09:00到次日09:00 | `ASSUME/时钟定义`；统一热浪、夜间与应急响应起点。三段为09–17、17–22、22–次09，不等于三个独立自然日 | M1—M5；`hours.PERIODS`、`capacity_on_service_day` | 日历日期错位会改变夜间供给和到达后容量 | 需要前一开业日、当日、后一日的日历上下文；检查午夜、09点、闭站和跨夜边界 |
| A06 需求时段份额及群体混合 | `ASSUME`；当前全区共用有住所/无住所的混合时段曲线，样本中的无住所访客比例不能升级成全市人口比例 | M1；`split_demand_mixed`、`meta.unsheltered_share` | 夜间缺口、延时价值和站点排序可能变 | 扫描群体比例与曲线；有区级逐时到访后替换。不能预先声称细化时段不会改变定性结论 |
| A07 区域以代表位置计算可达性 | `ASSUME`；缺区内人口加权空间分布。合成代表位置不能自动称为真实人口质心 | M3可行边；`access.csv`、区坐标 | 区内服务覆盖可能高估或低估，**误差没有固定方向**，选址排序亦可能改变 | 用人口加权网格/tract与实际出行样本检验；不能把真实可达率夹在“质心”与“最近边界点”之间 |
| A08 代理交通时间与阈值 | `ASSUME/DERIVED`；直线绕行、速度、候车与GTFS站点代理均非门到门实测。阈值为可配置管理情景，不以“政策惯例”冒充来源 | M3；`max_minutes`、可达矩阵 | 代理误差可使可达性和相对排序任向变化；更长时间也不能证明原结论“更强” | 保持同一交通矩阵比较政策；公交应含直达步行替代、真实服务日、候车换乘与可乘班次。GTFS是计划时刻，不是实际运行 |
| A09 固定中心容量未知；MCH为题设上限 | 固定站的工作容量为 `ASSUME`，MAG不提供接待上限；MCH的250是每运营日最大人次，不是并发人数、平均停留时间或保证客流 | M2、M3；站点 `capacity`、`source_capacity` | 供给绑定程度、增车收益和公平代价都会变 | 逐站测吞吐/排队/人员；扫容量并查看利用率与未满足。容量放宽也不保证增车始终有效：存在需求饱和与不可达 |
| A10 开放窗口内均匀吞吐 | `ASSUME`；用日接待上限除该开业窗口小时数得人次/小时，缺逐时处理率 | M2；`capacity_on_service_day` | 高峰排队、短时拥堵和到达后服务量可能偏差 | 补逐时到访与排队；用时变处理率对照；跨日期使用各自开业窗口，不合并周内最早开门与最晚关门 |
| A11 延时保留固定日接待上限 | `ASSUME`；延时把既定日容量分配到更长窗口，并未另设更多人员或更多日吞吐 | M2、M6；`policy.evaluate` | 当前延时收益来自时间匹配；不能说加班自动增加总接待能力 | 若新增员工提高日吞吐，必须同时有报价和处理率数据，修改容量/成本后重跑 |
| A12 资料未知时段采用保守零供给 | `ASSUME/数据处置`；MAG空白、缺字段、日期越界和明确 `Closed` 含义不同。零供给是计算策略，不是证据证明关门 | M2；`realnet.calendar_for_date`、`calendar_by_day` | 未知时段较多时缺口可能高估；快照不是完整全年库存 | 分列 source status 与 availability policy；保留日期/节假日与空值。延时只作用于已知营业日；`unknown_hours='error'` 可拒绝缺失 |
| A13 未满足需求不跨日排队 | `ASSUME`；热暴露服务不能无依据地推迟到次日；没有跨日行为、累积热损伤模型 | M1、M4；每天独立输入需求 | 不能解释连续暴露健康损伤、重复人次或行为惯性 | 留出逐日到访与拒绝服务序列；如需排队状态须另加守恒与参数，不由当前结果推健康风险 |
| A14 公平用日未满足率，保留全区指标 | `定义/PLAN`；将三个时段总服务合并后计算 `U_i/D_i`，零需求区不除零。Gini和最差率衡量不同方面 | M3；`solve_assignment_periods`、`equity_summary` | 换指标、换豁免集合可改变公平排序；效率最优解的某个Gini不能当作全局最公平 | 同时报 `worst_unmet_ratio`、`worst_unmet_ratio_nonexempt`、`equity_exempt`。公平版本可按全固定站+全部候选点推导结构性豁免，但必须公开名单；不从全区统计删除这些区 |
| A15 静态p固定，动态保持车队资源一致 | `SCENARIO`；对给定p枚举有限候选组合。空闲容量不等于可移除资产，也不把固定网络当移动车队 | M3—M5；`solve_static`、`solve_week_dp` | 允许多个车同站、新站、许可约束后行动集会变 | 明示p、候选点、固定站、时段与共享外生输入；报告有限行动集，不用复杂度代替精确性说明 |
| A16 Q3当天迁移、初始部署已就绪 | `ASSUME`；状态为每日部署组合；车辆并行，行驶和搭建由代理时间给出。模型拒绝任一大于24小时的迁移，不假装跨日到达已完成 | M4；`solve_week_dp`、`move_time_hours` | 有跨日运输、出车准备、车组数不足时，现有状态不足；收益可能高估 | 路线和实际搭建测试；补人员/许可后筛选。`top_k=0` 全状态，正K是受限状态启发式，输出 `search_status` |
| A17 Q4站点失效与车辆失效分开 | `SCENARIO/ASSUME`；关站不等于损失车辆；坏车仅从实际部署中移除。健康车辆到达后按剩余窗口计算服务 | M2、M5；`plan_response` | 若设备、道路、供电、人员或许可恢复慢于代理时滞，24小时方案可能不可执行 | 比较相同冲击的“不搬”与调度；区分并行/串行人员。小车队精确枚举与大车队启发式须按输出标识，保留时限和可行性 |
| A18 Q5拥有、购买、开工、闲置分开 | `资源守恒`；允许买而暂不启用，停运保留资产。当前不建报废，`retire=0` | M6；`plan_investment` | 把停运当丢失会重复采购；强制新购即开工会漏掉提前备车方案 | 检查 `owned_before + buy − retire = owned`、`active≤owned`、`idled=owned−active`；资产清单和独立小模型穷举 |
| A19 Q5成本、预算和时间假设 | `ASSUME`；每年资本+所有开工车运维+年度延时/接驳；初始购置沉没。合同可逐年取消；储存费/退化/通胀/提前期/预算结转未建模，不是现实确认等于零 | M6；`annual_cost`、`COST`、`BUDGETS` | 购置时点、保留库存、预算可行与方案排序可能变 | 真实供应商和用工报价；成本扫描记录行动翻转区间。采购慢于一年须加在途状态，不沿用即时采购结论 |
| A20 Q5为预知情景规划基准 | `SCENARIO`；五年外生热路径给定，代表日重复数默认1。DP不是未知未来下的随机最优，也不是五年实测预测 | M6；`plan_investment`、`scenario_evaluator` | 需求/预算预测误差与非预知决策会改变跨期价值 | 对照共享外生路径、相同行动集的滚动策略；实际年度更新用新观测，披露 `operating_days` |

## 数据不能识别什么，以及采用的处置

| 当前资料 | 能支持的量 | 不能识别的量 | 本轮处置 |
|---|---|---|---|
| 部分中心周报、访客调查 | 指定站点、期间和样本的已实现到访/访客特征 | 全市潜在需求、未到访者分布、各群体参与率 | 需求式保留工作假设，结果为条件服务情景；不声称潜在需求校准通过 |
| MAG公开站点快照 | 该快照中的类型、坐标、日期和时段原文 | 全季完整站点库存、实际每日开门、容量 | 逐日解析并保留unknown；容量单独标假设；官方字段重建检验只验证数据变换 |
| 官方村级报告及边界、ACS tract表 | 各自年份/地域口径的统计量与不确定性 | 同年同口径的所有12区参数、家庭级需求 | 不混同ACS2018–22和2020–24；无车家庭不可把全县比率填到每区；中位收入分组插值仍为代理 |
| GTFS与坐标 | 计划班次/服务日、路线上站序、地理位置 | 实际延误、门到门旅行、可用座位和热暴露步行成本 | 不把站点距离当公交可达实测；保持交通模型对照与直接步行备选 |
| 人员方案、异地移动设施案例与文献 | 运营障碍、参数参考范围 | Phoenix MCH正式报价、容量、因果健康收益 | 固定为显式假设并做扫描，现场建议限制为采集/试点/复算流程 |

## 有限网络的结构结论如何写

“给定当前需求代表位置、固定站点和这8个候选点、交通模型与阈值，某区无可行边”是条件网络结论。它不能推出这个真实社区无法被任何移动站服务，也不能推出新增候选点、调整时段或交通后仍然不可达。`p=8` 也只是部署当前八点，不是遍历所有城市位置。

因此，旧版“D08任何选点都救不了”“真实网络仅若干区可达就是实证覆盖率”“距离公交站很远就是硬缺口”等无条件表述全部撤回。应引用具体输出中的 `zero_access_districts`、`reachable_counts`、`equity_exempt` 及其输入指纹和参数；数值变化后重新计算，不在假设卡锁死旧结果。

## 使用与复核记录

每条主要结论连到假设ID、M公式、输入类别、函数、配置和结果字段；改变其中一项后重跑对应对照。数值对拍证明实现，官方字段留出检验证明限定的数据处理环节，敏感性证明给定范围的条件稳健性；三者均不能代替实际服务响应验证。

作者自查、另一代理/队员复核、三人独立复述分别留记录。本文没有替三位队员勾选“已共同掌握”，也没有以删除AI参与记录换取形式合规。
